# Python 程序压力测试器

当前版本 **v0.2.0**（图形界面的窗口标题和界面右下角都会显示版本号）。

Windows + Python 3.12（3.9 以上都能跑），**只使用标准库，没有任何第三方依赖**。

它做一件事：按你写的规则随机生成一大堆输入，**每一组输入都单独启动一次**被测试程序，
最后告诉你哪些输入把它搞崩了、哪些输入让它超时了。

再加一个参考程序（`--ref`），它还能顺便**对拍**：同一份数据同时喂给两个程序，
比 stdout，把「答案不一致」的那几组也挑出来 —— 这就是刷题时最常用的"对拍"。

有命令行和图形界面两种用法，核心逻辑都在 `main.py` 里，界面只是一层壳。

---

## 1. 文件清单

| 文件 | 说明 |
| --- | --- |
| `main.py` | 压力测试器本体（命令行） |
| `app.py` | 图形界面外壳（tkinter，只用标准库） |
| `gen.py` | 数据生成规则（示例，真正用时按你的被测试程序改它） |
| `example_target.py` | 故意留了两个 bug 的被测试程序，用来试跑 |
| `example_ref.py` | 正确的参考程序，用来试跑对拍 |
| `templates/` | 6 个开箱即用的 `gen.py` 模板 + 配套示例目标程序 + `模板选用指南.md` |
| `README.md` | 本文件 |
| `打包说明.md` | 怎么用 PyInstaller 把 `app.py` 打成双击就能运行的 exe |
| `_selftest/checks.py` | `main.py` 的自检脚本（可选，30 多项检查） |
| `_selftest/ref_check.py` | 对拍功能的自检脚本（可选，30 多项检查） |
| `_selftest/gui_check.py` | 界面的自检脚本（可选，30 多项检查） |

不需要 `_selftest` 目录的话，整个删掉即可。

## 2. 马上试一下（命令行）

```bat
python main.py example_target.py --seed 123
```

屏幕会逐组打印进度，最后一行是统计。这个示例程序的结果大致是：

```
通过 151 组 / 崩 47 组 / 超时 2 组
```

同时会在当前目录写出 `fail_1.txt` … `fail_5.txt`（最先崩的 5 组）。

## 3. 图形界面怎么用（app.py）

```bat
python app.py
```

窗口从上到下是这样几块：

1. **被测试程序**：点「选择被测试程序…」挑一个 `.py`。
2. **参考程序**：点「选择…」挑一个 `.py` 做对拍；**留空就是只做压力测试**（只看崩没崩、超没超时）。
3. **Python 解释器**：用哪个解释器去跑 `main.py`。
4. **参数**：测试组数（默认 200）、超时秒数（默认 1.0）、随机种子（留空＝每次随机）。
5. **gen.py 编辑区**（左半边）：直接在这里改数据生成规则，点「保存 gen.py」存盘。
   点「开始」时如果还有没保存的改动，会自动先保存，保证跑的就是你看到的那份。
   左上角还有 **「套用模板：」下拉框**，一键把 `templates/` 里的模板填进来，见下一节。
6. **开始 / 停止**：跑起来以后界面照样能点、能滚、能停 —— 它是用后台线程读 `main.py` 的输出，
   不占主线程，所以不会卡死。
7. **实时日志**（右半边）：`main.py` 的每一行原样贴过来，通过是绿的、崩溃/不一致是红的、
   超时是橙的、参考程序出错是紫的；跑完以后，结尾那行统计会单独显示在日志上方的大横条里
   （对拍模式下横条会一起显示「不一致 k 组」，参考程序出过错还会多一行提示）。
8. **失败用例**：跑完列出这次的 `fail_*.txt`、`diff_*.txt`、`ref_fail_*.txt`（每行前面标了类别），
   **点一下就在界面里弹出预览小窗**看内容 —— 不用再去资源管理器里找文件了。
   小窗的标题就是文件名，内容区只读但**可以拖动选中、可以 Ctrl+C 复制**
   （`diff_*.txt` 顶部有「复现命令」和「第一处不同」，所以复制很常用）；
   底部有三个按钮：「复制全部内容」「定位到文件夹」「关闭」。
   同一时间只会有一个预览小窗：点别的文件内容直接换过去，重复点同一个文件只是把它提到最前面，
   不会开出一堆窗口。预览窗不阻塞主界面 —— 看着看着还能继续开始下一轮测试。

「停止」会把 `main.py` 连同它启动的被测试进程整棵进程树一起结束掉，
不会留下还在后台空转的 `python.exe`；打开文件夹、杀进程这些耗时动作都在后台线程里做，界面不卡。

### 怎么用模板（一键套用）

`gen.py` 编辑区顶部有个 **「套用模板：」下拉框**，里面列着 `templates/` 里所有 `gen_*.py`
（数组、字符串、多组数据、矩阵、图、询问，共 6 个），第一项固定是「（不使用模板）」。

用法就四步：

1. 用「选择被测试程序…」挑好你的程序；
2. 在「套用模板：」里选一个最像的（比如数组题选 `gen_array.py`）；
3. 编辑区立刻换成模板内容 —— **这时候还没写盘**，编辑区右上角会显示
   「已套用模板 gen_array.py（还没保存）」；
4. 按题目改那两三行（模板顶部注释里标着 `← 改这里`），点 **「保存 gen.py」**，然后就能点「开始」了。

几个细节：

* 编辑区里有**没保存的改动**时再选模板，会先弹一句确认：
  「当前 gen.py 有未保存的改动，套用模板会覆盖它，确定吗？」
  —— 点「否」就什么都不做，下拉框退回「（不使用模板）」，不会偷偷冲掉你正在写的规则。
* 选「（不使用模板）」不会改动编辑区（它就是"没套模板"的默认状态）。
* 想反悔：点「重新载入」就把磁盘上的 `gen.py` 读回来，等于放弃刚才套用的模板。
* 找不到 `templates/` 目录时，下拉框会显示「（没找到 templates 目录）」并变灰。
  查找顺序：先 `app.py`（打包后是 exe）同目录，再 `main.py` 同目录。

命令行用法（等价，适合写脚本/批处理）：

```bat
python main.py 你的程序.py --gen templates/gen_array.py --seed 123
```

模板各自适合什么题、要改哪几行，见 `templates/模板选用指南.md`。

## 4. 怎么用在你自己的程序上

```bat
python main.py 你的程序.py
python main.py 你的程序.py --seed 123
python main.py 你的程序.py --seed 123 --count 500 --timeout 2
```

要求：

* **被测试程序**：一个 `.py` 文件，从标准输入读数据，正常结束时返回码为 0。
  它会以「文件所在目录」为工作目录运行，所以程序里读同目录的文件没问题。
* **`gen.py`**：放在 `main.py` 同目录（找不到时会再去被测试程序同目录找），
  里面必须有一个 `gen()` 函数：

  ```python
  def gen() -> str:
      return "3\n1 2 3\n"      # 返回值就是一组完整的输入
  ```

  每次调用 `gen()` 生成一组数据，返回的字符串会被整段写进被测试程序的 stdin，然后关闭 stdin。

不想自己从零写 `gen.py`，就去 `templates/` 里挑一个最像的模板，改两三行就能用；
挑哪个、改哪里，见 `templates/模板选用指南.md`。
用图形界面的话，直接在下拉框里选（见第 3 节的「怎么用模板」）；命令行等价写法：

```bat
python main.py 你的程序.py --gen templates/gen_array.py --seed 123
```

## 5. 对拍：顺便查答案对不对（--ref）

**"崩了 / 超时"只能发现程序挂掉，发现不了"跑完了但答案错了"。** 加一个参考程序就能补上这一块：
每一组数据同时喂给被测试程序和参考程序，然后比两边的 stdout。

三行示例（最后一行用的是仓库里现成的例子，直接就能跑）：

```bat
python main.py 我的程序.py --ref 参考程序.py --seed 123
python main.py 我的程序.py --ref 参考程序.py --count 500 --timeout 3
python main.py example_target.py --ref example_ref.py --seed 123
```

判定规则（这块最容易出错，照这个来）：

| 情况 | 判定 |
| --- | --- |
| 被测试程序崩了 / 超时 | 照旧记 **崩溃** / **超时**（这一组不比对，参考程序也不会被启动） |
| 参考程序崩了 / 超时 | 记 **参考程序出错**，单独计数 |
| 两边都正常退出（返回码 0），输出一样 | **通过** |
| 两边都正常退出，输出不一样 | **答案不一致** |

**参考程序出错绝对不算成"被测试程序错了"** —— 免得你去改一个本来没错的程序。
它会在统计行下面单独提醒一句「参考程序自身出错 j 组，请先修参考程序」。

比输出时忽略这些（避免假报警）：**每行行尾空白、输出末尾的空行、行尾的 `\r`**。

## 6. 判定标准

| 情况 | 判定 |
| --- | --- |
| 返回码不是 0 | **崩溃** |
| 运行时间超过 `--timeout`（默认 1 秒） | **超时** |
| 返回码是 0，且（没开对拍，或和参考程序输出一致） | **通过** |
| 返回码是 0，但和参考程序输出不一致 | **答案不一致**（只在 `--ref` 时可能出现） |
| 参考程序自己崩了 / 超时 | **参考程序出错**（只在 `--ref` 时可能出现） |

超时的进程会被杀掉（Windows 上先 `taskkill /F /T`，再对直接子进程 `kill()` 兜底），
不会留在后台继续跑。

## 7. 输出

屏幕：每组一行进度（`--quiet` 可以关掉），最后是统计行。

文件：每个失败文件顶部都有一行 **「复现命令」**，照着复制就能把这一批数据重新跑出来。

| 文件 | 最多几个 | 里面有什么 |
| --- | --- | --- |
| `fail_1.txt` … `fail_5.txt` | 5 | 崩溃那一组的完整输入 + 被测试程序的报错信息 |
| `diff_1.txt` … `diff_5.txt` | 5 | 答案不一致那一组：输入 + 两边的输出 + **第一处不同在第几行第几列** |
| `ref_fail_1.txt` … `ref_fail_3.txt` | 3 | 参考程序自身出错的那一组：输入 + 参考程序报了什么错 |

超时不写文件（按需求，只要求存崩溃/不一致的输入）。同名文件会被覆盖。

## 8. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `target` | 必填 | 被测试的 `.py` 文件 |
| `--ref 参考程序.py` | 不给 | 给了就开对拍：每组数据同时喂给两个程序并比 stdout |
| `--count N` | 200 | 测试组数 |
| `--timeout 秒` | 1.0 | 单组超时时间（两个程序各算各的） |
| `--seed N` | 随机 | 随机种子，见下节 |
| `--gen 路径` | 自动找 | 指定 `gen.py` 的位置 |
| `--outdir 目录` | 当前目录 | 失败文件写到哪里 |
| `--python 解释器` | 当前解释器 | 用哪个 Python 跑被测试程序（参考程序也用同一个） |
| `--quiet` | 关 | 不打印逐组进度 |

## 9. 统计行

```
不给 --ref：  通过 151 组 / 崩 47 组 / 超时 2 组
给了 --ref：  通过 151 组 / 崩 47 组 / 超时 2 组 / 不一致 3 组
```

参考程序出错时，统计行下面再补一句：

```
参考程序自身出错 2 组，请先修参考程序
```

## 10. 随机种子与复现

* 加了 `--seed 123`：每次运行生成的 200 组数据**完全一样**，失败组号、失败文件里的输入也都一样。
* 不加 `--seed`：程序自己随机挑一个种子并打印出来（`随机种子 : 1384166458`），
  想复现那一次，就照着加 `--seed 1384166458`。

它是怎么做到可复现的：运行 `gen()` 之前，压力测试器已经对全局 `random` 模块播种，
并且往 `gen.py` 模块里注入了两个名字：

```python
SEED   # 本次运行的随机种子（整数）
rnd    # random.Random(SEED)，一个已经播好种的独立发生器
```

所以在 `gen.py` 里用 `random.randint(...)` 或者 `rnd.randint(...)` 都行，都能被 `--seed` 复现。
**不要**用没播种的随机源（`random.Random()`、`os.urandom()`、`time.time()` 等），
也不要在 `gen.py` 里自己定义 `SEED` / `rnd`，那样就复现不了了。

另外，被测试程序是用固定 `PYTHONHASHSEED=0` 启动的，避免集合/字典顺序带来的随机差异。

## 11. 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部通过 |
| 1 | 出现了崩溃 / 超时 / 答案不一致 / 参考程序出错（最后一种不代表被测试程序有错） |
| 2 | 用法/环境错误（被测试程序、参考程序、`gen.py`、`gen()` 有问题等） |

## 12. 遇到问题怎么办

* **对拍时"参考程序出错"一大堆？** 先单独跑一遍参考程序看它自己怎么挂的，
  或者先用 `--count 20` 小规模跑；`ref_fail_1.txt` 里有它的完整报错。
* **出现假的不一致？** 先看 `diff_*.txt` 里的「第一处不同」和两边输出。
  注意程序里如果有时间、随机数、浮点误差、字典/集合顺序导致的输出差异，对拍就会报警——
  这类程序不适合直接对拍，或者让两边都输出可比较的规范化结果。
* **中文乱码？** 数据按 UTF-8 喂给被测试程序，输出也按 UTF-8 读回来；
  如果程序自己按别的编码输出，文件里会有 `?` 之类的替代字符。
* **机器慢，误报超时？** 把 `--timeout` 调大（比如 `--timeout 3`）。
* **想存更多失败用例？** 改 `main.py` 顶部的 `MAX_FAIL_FILES` / `MAX_DIFF_FILES` / `MAX_REF_FAIL_FILES`。
* **被测试程序需要命令行参数？** 目前不支持，压力测试器只给它 stdin。
* **想打成 exe 双击运行？** 见 `打包说明.md`。
