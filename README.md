# Python 程序压力测试器

Windows + Python 3.12（3.9 以上都能跑），**只使用标准库，没有任何第三方依赖**。

它做一件事：按你写的规则随机生成一大堆输入，**每一组输入都单独启动一次**被测试程序，
最后告诉你哪些输入把它搞崩了、哪些输入让它超时了。

有命令行和图形界面两种用法，核心逻辑都在 `main.py` 里，界面只是一层壳。

---

## 1. 文件清单

| 文件 | 说明 |
| --- | --- |
| `main.py` | 压力测试器本体（命令行） |
| `app.py` | 图形界面外壳（tkinter，只用标准库） |
| `gen.py` | 数据生成规则（示例，真正用时按你的被测试程序改它） |
| `templates/` | 6 个开箱即用的 `gen.py` 模板 + 配套示例目标程序 + `模板选用指南.md` |
| `example_target.py` | 故意留了两个 bug 的被测试程序，用来试跑 |
| `README.md` | 本文件 |
| `打包说明.md` | 怎么用 PyInstaller 把 `app.py` 打成双击就能运行的 exe |
| `_selftest/checks.py` | `main.py` 的自检脚本（可选，30 多项检查） |
| `_selftest/gui_check.py` | 界面的自检脚本（可选，20 多项检查） |

不需要 `_selftest` 目录的话，整个删掉即可。

## 2. 马上试一下（命令行）

```bat
python main.py example_target.py --seed 123
```

屏幕会逐组打印进度，最后一行是统计。这个示例程序的结果大致是：

```
通过 151 组 / 崩 47 组 / 超时 2 组
```

同时会在当前目录写出 `fail_1.txt` … `fail_5.txt`（最先崩的 5 组）。

## 3. 图形界面怎么用（app.py）

```bat
python app.py
```

窗口从上到下是这样几块：

1. **被测试程序**：点「选择被测试程序…」挑一个 `.py`；旁边还能指定用哪个 Python 解释器去跑。
2. **参数**：测试组数（默认 200）、超时秒数（默认 1.0）、随机种子（留空＝每次随机）。
3. **gen.py 编辑区**（左半边）：直接在这里改数据生成规则，点「保存 gen.py」存盘。
   点「开始」时如果还有没保存的改动，会自动先保存，保证跑的就是你看到的那份。
4. **开始 / 停止**：跑起来以后界面照样能点、能滚、能停 —— 它是用后台线程读 `main.py` 的输出，
   不占主线程，所以不会卡死。
5. **实时日志**（右半边）：`main.py` 的每一行原样贴过来，通过是绿的、崩溃是红的、超时是橙的；
   跑完以后，结尾那行统计会单独显示在日志上方的大横条里。
6. **失败用例**：跑完列出这次的 `fail_1.txt` … `fail_5.txt`，**点一下**就用系统默认程序打开。

「停止」会把 `main.py` 连同它启动的被测试进程整棵进程树一起结束掉，
不会留下还在后台空转的 `python.exe`。

## 4. 怎么用在你自己的程序上

```bat
python main.py 你的程序.py
python main.py 你的程序.py --seed 123
python main.py 你的程序.py --seed 123 --count 500 --timeout 2
```

要求：

* **被测试程序**：一个 `.py` 文件，从标准输入读数据，正常结束时返回码为 0。
  它会以「文件所在目录」为工作目录运行，所以程序里读同目录的文件没问题。
* **`gen.py`**：放在 `main.py` 同目录（找不到时会再去被测试程序同目录找），
  里面必须有一个 `gen()` 函数：

  ```python
  def gen() -> str:
      return "3\n1 2 3\n"      # 返回值就是一组完整的输入
  ```

  每次调用 `gen()` 生成一组数据，返回的字符串会被整段写进被测试程序的 stdin，然后关闭 stdin。

不想自己从零写 `gen.py`，就去 `templates/` 里挑一个最像的模板，改两三行就能用；
挑哪个、改哪里，见 `templates/模板选用指南.md`。例如：

```bat
python main.py 你的程序.py --gen templates/gen_array.py --seed 123
```

## 5. 判定标准

| 情况 | 判定 |
| --- | --- |
| 返回码不是 0 | **崩溃** |
| 运行时间超过 `--timeout`（默认 1 秒） | **超时** |
| 返回码是 0 | **通过** |

超时的进程会被杀掉（Windows 上先 `taskkill /F /T`，再对直接子进程 `kill()` 兜底），
不会留在后台继续跑。

## 6. 输出

* 屏幕：每组一行进度（`--quiet` 可以关掉），最后一行是统计：

  ```
  通过 151 组 / 崩 47 组 / 超时 2 组
  ```

* 文件：**最先出现的 5 组「崩溃」** 各写一个文件，`fail_1.txt` 是第一次崩溃的那组，
  依次到 `fail_5.txt`（同名文件会被覆盖）。每个文件里同时有：

  * 这一组的完整输入数据；
  * 被测试程序的返回码、耗时、这次运行用的随机种子；
  * 被测试程序打印出来的全部内容，包括报错信息（Traceback）。

  超时不写文件（按需求，只要求存崩溃的输入）。

## 7. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `target` | 必填 | 被测试的 `.py` 文件 |
| `--count N` | 200 | 测试组数 |
| `--timeout 秒` | 1.0 | 单组超时时间 |
| `--seed N` | 随机 | 随机种子，见下节 |
| `--gen 路径` | 自动找 | 指定 `gen.py` 的位置 |
| `--outdir 目录` | 当前目录 | `fail_*.txt` 写到哪里 |
| `--python 解释器` | 当前解释器 | 用哪个 Python 跑被测试程序 |
| `--quiet` | 关 | 不打印逐组进度 |

## 8. 随机种子与复现

* 加了 `--seed 123`：每次运行生成的 200 组数据**完全一样**，崩溃的组号、
  `fail_*.txt` 里的输入也都一样，方便复现问题。
* 不加 `--seed`：程序自己随机挑一个种子，并把它打印出来（`随机种子 : 1384166458`），
  想复现那一次，就照着加 `--seed 1384166458`。

它是怎么做到可复现的：运行 `gen()` 之前，压力测试器已经对全局 `random` 模块播种，
并且往 `gen.py` 模块里注入了两个名字：

```python
SEED   # 本次运行的随机种子（整数）
rnd    # random.Random(SEED)，一个已经播好种的独立发生器
```

所以在 `gen.py` 里用 `random.randint(...)` 或者 `rnd.randint(...)` 都行，都能被 `--seed` 复现。
**不要**用没播种的随机源（`random.Random()`、`os.urandom()`、`time.time()` 等），
也不要在 `gen.py` 里自己定义 `SEED` / `rnd`，那样就复现不了了。

另外，被测试程序是用固定 `PYTHONHASHSEED=0` 启动的，避免集合/字典顺序带来的随机差异。

## 9. 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部通过 |
| 1 | 出现了崩溃或超时 |
| 2 | 用法/环境错误（文件找不到、`gen()` 不存在、`gen()` 自己抛异常等） |

## 10. 遇到问题怎么办

* **中文乱码？** 数据按 UTF-8 喂给被测试程序，输出也按 UTF-8 读回来；
  如果被测试程序自己按别的编码输出，`fail_*.txt` 里会有 `?` 之类的替代字符。
* **机器慢，误报超时？** 把 `--timeout` 调大（比如 `--timeout 3`）。
* **想存更多失败用例？** 改 `main.py` 顶部的 `MAX_FAIL_FILES`（默认 5）。
* **被测试程序需要命令行参数？** 目前不支持，压力测试器只给它 stdin。
* **想一次看全过程？** 去掉 `--quiet`；想只看结论就加 `--quiet`。
* **想打成 exe 双击运行？** 见 `打包说明.md`。
